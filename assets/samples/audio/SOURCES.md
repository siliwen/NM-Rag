# 音频测试素材说明

本目录的音频**只用于验证转写链路**，不进入正式知识库，也不随交付包发布。

## 1. `funasr_example_zh.wav`

| 项 | 说明 |
|---|---|
| 来源 | FunASR 官方测试样例（`isv-data.oss-cn-hangzhou.aliyuncs.com/ics/MaaS/ASR/test_audio/asr_example_zh.wav`） |
| 内容 | 5.5 秒中文女声，台词：「欢迎大家来体验达摩院推出的语音识别模型。」 |
| 用途 | 确认真实人声能被正确识别（不是只有合成音频能跑通） |
| 版权口径 | 模型官方公开的测试样例，仅作本地功能验证，再分发时请移除 |

## 2. `模拟口述史-皮影戏-*.wav` + `*.truth.json`

| 项 | 说明 |
|---|---|
| 来源 | **本机合成**（`code/scripts/make_oral_history_sample.py`，Windows SAPI 中文音色 Huihui） |
| 内容 | 第一人称皮影戏口述史，4 段 18 句 482 字，时长 149.7 秒 |
| 两个版本 | `无噪声`（干净）/ `含噪`（叠 12dB 白噪声，模拟现场录音） |
| 附带 | `.truth.json` 是**标准答案**：每句的文本与精确起止毫秒 |
| 用途 | 唯一能同时验证「字准率」和「时间戳误差」的素材 |

为什么不用网上现成的非遗音频：能找到的非遗录音**没有配套文本**，
没有标准答案就只能靠肉眼判断"看着差不多"，测不出 CER，也测不出时间戳偏了几秒。
合成音频的代价是它比真实口述史干净（无方言、无装订噪声、无多人抢话），
所以**这里的数字是上限，不是预期**。

刻意保留了三个真实特征：
- 段落之间 1.5 秒长停顿 → 检验切块会不会按话题断开
- 句间 0.3 秒短停顿 → 不应被切开
- `--rate -1` 放慢语速，接近老人讲话节奏

## 3. 评测产物

| 文件 | 说明 |
|---|---|
| `segments-*.json` | 识别出的句级时间戳原始结果，调阈值时可直接复用，不必重跑识别 |
| `eval-*.json` | 评测报告（CER / 时间戳误差 / 边界违规） |
| `*.transcript.txt` | 转写稿样例，可直接用编辑器改错字后回灌 |

注：`.gitignore` 里有 `*.wav`（为传承人原始录音准备的规则），所以音频本体不入库，
只有 `.truth.json` 与评测报告会提交。需要跑评测时按下面命令重新生成即可
（注意 SAPI 输出在不同 Windows 版本上可能略有差异，届时 `.truth.json` 需一并重新生成）。

复现命令：

```bash
cd code
# 造样本（含标准答案）
.venv\Scripts\python.exe scripts\make_oral_history_sample.py --out ..\assets\samples\audio\模拟口述史-皮影戏-无噪声.wav --rate -1
# 评测
.venv\Scripts\python.exe scripts\eval_asr.py ..\assets\samples\audio\模拟口述史-皮影戏-无噪声.wav
```

## 拿到传承人真实录音后要做什么

1. 放进本目录，按 `<传承人>-<项目>-<录制日期>.wav` 命名；
2. 先跑 `scripts/transcribe_audio.py 该文件 --max-seconds 180` 看前 3 分钟识别质量；
3. 方言重的话按「转写 → 导出稿 → 人工校对 → 回灌」走，不要直接把原始识别结果入库；
4. 把 CER 与错例记进 `AGENT.md`，作为是否需要在方言数据上微调的依据。

素材使用需配套传承人的**肖像与声音双授权书**（见 `docs/非遗传承人素材拍摄指引.md`）。
