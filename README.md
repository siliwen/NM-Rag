# NM-RAG · 非遗数字人讲解员的知识底座

面向高校非遗项目：把非遗传承人的形象做成**数字人讲解员**，观众现场提问，系统检索知识库后用传承人的声音作答。

本仓库当前是其中的 **RAG（检索增强生成）部分** —— 它已经能在本机离线跑通，可单独演示与评测。数字人渲染（LiveTalking）尚未接入。

> 设计原则：**最终必须本地部署、实时渲染**，不依赖任何第三方数字人云服务。
> 唯一允许联网与付费的环节是调用大模型 API。

## 现在能做什么

| 能力 | 状态 | 实测 |
|---|---|---|
| 文本入库 + 语义检索 | ✅ | hit@1 **84.6%** / hit@3 **96.2%** / MRR **0.904**（33 题评测集） |
| 有文本层的 PDF 入库 | ✅ | 17 页政府文件 → 8669 字 / 49 卡 / 1.5 秒，页码全对 |
| 扫描件 OCR 入库 | ✅ | 按页判有效字符数，不够的页自动 OCR（CPU 约 5 秒/页） |
| 口述史录音转写 | ✅ | 字准率 **93.87%**，时间戳中位误差 **138 ms**，RTF **0.081** |
| 会话状态机 + 打断 | ✅ | idle→listening→thinking→speaking，打断 300 ms 内生效 |
| 真实大模型问答 | ✅ | qwen-flash，首字 528 ms，越界问题会明确说"资料里没有" |
| 数字人渲染（LiveTalking） | ⬜ | 客户端已写好，等 GPU 实例 |

**136 个测试全绿**，全部离线（不联网、不占显存、不需要 GPU）。

## 快速开始

```bash
cd code
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt

# 跑测试（136 个，全部离线）
.venv\Scripts\python.exe -m pytest -q

# 启动服务 → http://127.0.0.1:8020/demo/
.venv\Scripts\python.exe scripts\serve.py
```

演示台左栏可以：灌入示例语料、粘贴文本入库、上传 PDF、上传录音，并一键跑检索评测。

> 只跑单元测试可以不装 `sentence-transformers`（设 `EMBEDDER=hash`），
> 但 hash 桩**没有语义能力**，它跑出来的分数不能当检索质量结论用。

## 几个不显然的设计决定

这些是从踩坑里换来的，详细理由见 `AGENT.md` 的 DEC 表。

- **向量库用 SQLite 的 float32 BLOB + numpy 检索**，不引入 Chroma。非遗规模（几千卡片）下性能完全够，少一个重依赖。
- **库里记录向量指纹（模型名 + 维度）**。`hash` 桩与 `bge-small-zh` **同为 512 维**，只比维度发现不了换过模型——旧向量会被当有效数据继续用，不报错，结果是垃圾。指纹不符或缺失就自动重算。
- **检索必须混合**：纯向量会漏非遗专名，BM25 兜字面匹配。但关键词权重按 embedder 能力自动取值——实测纯向量 hit@1 88.5%，加 0.6 权重的关键词反而降到 80.8%。
- **越界问题不能靠检索分数阈值拦**。实测越界题峰值 0.44、正常题最低 0.48，区间重叠，交大模型判断。
- **PDF 逐页切块**。整篇切时页码靠字符偏移反推，卡片跨页就说不清出自哪页。
- **禁止 PyMuPDF（AGPL）**，改用 `pypdfium2`（Apache-2.0）+ `rapidocr-onnxruntime`（Apache-2.0）。
- **FunASR 必须传 `sentence_timestamp=True`**。不传时它正常返回 `text`、不报错，但没有句级时间戳，所有卡片时间戳退化成 0，用户点溯源永远跳到开头。
- **切块要看两重证据**：识别段时间差 **+ 波形静音**。标点模型会把跨静音的两句并成一句，合并后时间差是 0，只看时间差必漏。

## 合规与许可

- 代码依赖均为 Apache-2.0 / BSD / MIT；**AGPL 组件（PyMuPDF、CyberVerse）不可用于交付**。
- 使用传承人的肖像与声音，**必须取得双授权书**（由学校出面签署）。
- AI 生成的讲解内容需按规定标注。
- 方言口述史的转写结果**必须人工校对后才能入知识库**，否则错字会被当成"传承人原话"讲出去。
